# Working instructions

## Skills

Before writing, changing, or restructuring code, check the skill list and read the matching skill. If there is even a small chance one applies, read it before acting — including before your first edit, not after it.

- A file too large, too many responsibilities, or asked to split / merge / simplify / tidy / restructure → `refactoring-safely`
- About to hand-write a helper, parser, validator, retry loop, config loader, or start a new module, package, script, or repo → `preferring-existing-libraries`
- About to add, change, or remove a comment or docstring → `writing-code-comments`

Announce "Using <skill> to <purpose>" before following a skill.
